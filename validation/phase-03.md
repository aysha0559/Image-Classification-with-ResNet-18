## Notes (non-blocking)
- **JPEG mismatch reproduced.** Our code path matches the reference, and the transcribed reference gives identical output in this environment, so the difference comes from outside the repo's logic. Against CIFAR-10-C on 1,000 test images: identical images 0.014-0.019, identical values 0.52-0.67, max difference 82-99 levels. The human accepted this and Phase 10 must disclose it. The cause (JPEG library version) remains unconfirmed.
- **The tests do not pin the severity parameter values.** In a scratch copy, changing JPEG severity 5 quality from 40 to 45 or contrast severity 5 from 0.15 to 0.2 left all 83 tests in `test_corruptions.py` and `test_transforms.py` passing. V6 confirms the values are correct today, but a later accidental edit would not be caught. A small test comparing the 4 constants with the reference values would close this.
- **`test_batch` is opened while loading the training set, but only for a checksum.** The audit in V4 showed it because `torchvision.datasets.CIFAR10.__init__` runs `_check_integrity` over the train and test files before reading the selected split. Its images are not loaded; `train=False` appears only in `get_test_dataset` (`src/data/cifar10.py:235`).
- `src/config.py` accepts `fog` in `corruption_aware.corruptions`; `build_train_transform` then rejects it. Confirmed as described in PROGRESS Known issues. It fails loudly, only later than it could.
- The leakage guard catches a new import in `corruptions.py` (2 tests fail in a scratch copy). As noted in Phase 02, it covers static imports and literal names only.
- All 4 transforms use the torchvision and Pillow pinned locally. Colab's versions are still UNKNOWN (Phase 00 deferral), and AugMix `all_ops` support and JPEG output could differ there. V7 should be re-confirmed on Colab in Phase 07.
- All scratch work stayed outside the repo; nothing in the repo was changed except this file.
